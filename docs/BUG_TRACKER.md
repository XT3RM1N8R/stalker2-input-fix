# Stalker 2 Input Fix: Master Bug Tracker
*A comprehensive record of every architectural flaw, edge case, and Windows OS quirk conquered during the development of this ASI Loader.*

## The 5 Architectures (Project Evolution)
We traversed five entirely different architectures to find the perfect proxy vector:
1. **GameInput (`gameinput.dll`):** Initial COM proxy. Abandoned due to VTable polymorphism and TOCTOU thread races.
2. **DXGI (`dxgi.dll`):** Global DirectX wrapper. Abandoned due to mod conflicts (Special K, DLSS).
3. **XInput (`xinput1_4.dll`):** Flat API proxy. Abandoned because Unreal Engine 5's `SetDefaultDllDirectories` dynamically bypassed the local folder.
4. **HID (`hid.dll`):** Statically imported OS driver. Abandoned because Windows 11 `ProcessMitigationImageLoadPolicy` forcefully bypassed the local folder to prevent OS hijacking.
5. **Version (`version.dll`):** The final, invincible MASM ASI Loader. Allowed by the OS Loader, completely external to the engine, and mod-compatible.

---

## 1. The COM & Loader Gauntlet (The GameInput Era)
* **The Shutdown Crash (Octuple Guard):** Windows unloading our DLL before Steam (`DLL_PROCESS_DETACH`), causing a fatal crash on game exit. **Fixed** by intentionally omitting the detach routine and leaking the Steam listener memory to the OS.
* **Dynamic Unloading (Quattuordecuple Guard):** COM forcefully unloading our proxy mid-game (`DllCanUnloadNow`). **Fixed** by pinning the DLL in memory (`GET_MODULE_HANDLE_EX_FLAG_PIN`).
* **Loader Lock Deadlock (Quindecuple Guard):** Spawning threads or calling `LoadLibrary` inside `DllMain`. **Fixed** by pivoting to low-level OS DLLs (`version.dll`) which only rely on `ntdll`, safely bypassing the lock constraints of higher-level DLLs.
* **VTable Polymorphism (Sexdecuple Guard):** Double-hooking the same COM interface address due to complex C++ inheritance. **Fixed** by abandoning COM entirely for flat C-APIs (XInput/RawInput).
* **TOCTOU Array Corruption (Septendecuple Guard):** Thread-racing on routing arrays when managing COM interfaces. **Fixed** by abandoning COM for flat C-APIs, requiring zero routing arrays.
* **The Background Thread Handle Leak (Sexvigintuple Guard):** Spawning the background worker thread using `CreateThread` but failing to close the returned handle, permanently leaking kernel object memory. **Fixed** by wrapping the call in `CloseHandle()`.

## 2. Hooking & State Management (The XInput/RawInput Era)
* **The Infinite Recursion Loop:** Our proxy trying to MinHook itself (when we were `xinput1_4.dll`), causing a Stack Overflow. **Fixed** by masquerading as an external DLL (`version.dll`) and MinHooking XInput safely from the outside.
* **The Stuck Button Bug:** Returning an error code to the engine without clearing the state memory, causing Unreal Engine to "stick" the last pressed button indefinitely. **Fixed** by strictly calling `memset(pState, 0, 16)` on every XInput hook.
* **The Secret Microsoft Ordinal:** Missing the hidden `XInputGetStateEx` API allowed inputs to bleed through. **Fixed** by dynamically tracking down and hooking `(LPCSTR)100`.
* **The UI Bleed-Through:** Unreal Engine reading gamepads as keyboards for menu navigation. **Fixed** by explicitly hooking and wiping `XInputGetKeystroke`.
* **The Permanent Input Lockdown (Steam Crash):** If Steam crashes or is forcefully closed while the overlay is open, the "deactivated" callback never fires, permanently locking the user out of their controller until the game is restarted. **Fixed** by adding a 1Hz Background Watchdog that monitors `GameOverlayRenderer64.dll`'s memory presence and forcefully disables the firewall if Steam vanishes.

## 3. Steam Overlay Caller Whitelisting (The Steam Interception)
* **Blinding the Overlay:** Our proxy returning errors to the Steam Big Picture UI, completely breaking overlay navigation. **Fixed** by building the `IsCallerSteam` Whitelist using `_ReturnAddress()` to check if the caller is a Steam DLL.
* **The Whitelist Framerate Tank (Cache-Miss):** Spamming `GetModuleHandleA` for `steamclient64.dll` 1000 times a second when the DLL isn't physically injected into the game process. **Fixed** by caching the `NULL` result using a `static bool bInitialized` flag, resulting in a single execution.
* **The Garbage Memory Callback Ignorance:** Forgetting to explicitly initialize `m_nCallbackFlags = 0` in the Steam API struct, causing Steam's event dispatcher to read garbage memory and silently ignore our callback registration. **Fixed** by explicitly zeroing the flags.
* **The Struct Layout Corruption:** Inadvertently removing `m_nCallbackFlags` from the `CCallbackBase` struct, which would cause Steam to fatally corrupt our function pointers on write. **Fixed** by strictly adhering to the byte-perfect Steamworks SDK layout.

## 4. Pathing, Loader Bypasses & Security Mitigations (The HID/Version Era)
* **The Drive Letter Bomb (Absolute Links):** Hardcoding `C:\Windows` into the compiler forwarders. **Fixed** by building Naked MASM Assembly stubs to dynamically fetch the true System folder at runtime.
* **The Drive Letter Bomb (Background Thread):** Hardcoding `C:\Windows` into the XInput force-loader. **Fixed** by porting the exact same dynamic `GetSystemDirectoryA` fetch to the background thread.
* **The Uninitialized Path Crash:** Forgetting to check if `GetSystemDirectoryA` actually succeeded before appending text to it. **Fixed** by wrapping it in a strict `if` condition.
* **The Generic C++ ABI Hack:** Relying on `#pragma comment(linker)` directives which break across compiler updates. **Fixed** by returning to pristine MASM naked assembly (`jmp qword ptr`).
* **The UE5 Anti-Hijacking Bypass:** Unreal Engine 5 using `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` to explicitly ignore local dynamic DLLs (`xinput1_4.dll`). **Fixed** by pivoting to a statically imported DLL.
* **The Windows 11 ImageLoadPolicy Block:** The Windows Kernel actively blocking the loading of semantically accurate system drivers (`hid.dll`) from the local application directory as an anti-malware mitigation. **Fixed** by pivoting to the industry-standard `version.dll`.

## 5. User Experience & Mod Compatibility (The DXGI Era)
* **Mod Conflicts (Special K / ReShade):** Wrapping DirectX APIs (`dxgi.dll`) creates severe loading order nightmares with other visual mods. **Fixed** by pivoting to `version.dll`.
* **The RawInput Freeze Rule:** Our initial code allowed the game's camera to spin while using the overlay. **Fixed** by intentionally removing the `RIM_TYPEHID` filter to indiscriminately freeze all of the game's RawInput (Mouse & Keyboard included) while the overlay is open.
## 6. The Asynchronous Input Nightmare (WGI & Desktop Configuration)
* **The Background WGI Thread Race Condition:** Unreal Engine 5's WGI (Windows.Gaming.Input) initialization occurred immediately at startup. Because our hooks were injected via a background worker thread to avoid Loader Lock, UE5 outran our hooks, cached the unhooked COM pointers, and completely bypassed our firewall. **Fixed** by abandoning the background thread and injecting all MinHook API blocks synchronously inside DllMain, halting UE5's WinMain execution until the firewall was completely armed.
* **The 4-Layer COM Interceptor (WGI):** WGI relies heavily on COM interfaces and VTables, which are notoriously difficult to hook safely. **Fixed** by building a 4-layer MinHook interceptor chain (RoGetActivationFactory -> dd_RawGameControllerAdded -> EventHandler::Invoke -> IRawGameController::GetCurrentReading) that safely zeroes the DualSense arrays before UE5 can read them.
* **The Desktop Configuration Message Bomb:** Even with controllers entirely blocked, Steam's global "Desktop Configuration" was synthesizing fake Windows Keyboard events (e.g. VK_DOWN) from the controller and injecting them into the game's message pump while the overlay was open, allowing the user to navigate the menu. **Fixed** by hooking PeekMessageW/PeekMessageA and nullifying all WM_KEYDOWN and WM_MOUSEMOVE messages via WM_NULL while the overlay is active.
## 7. The Man-In-The-Middle Bypass (Steam API Hooks)
* **The Whitelist Defeat:** We originally used _ReturnAddress() to whitelist GameOverlayRenderer64.dll so that the Steam UI could still read inputs when the game was blocked. However, Steam injects its own MinHook interception *after* our ASI Loader. Thus, when Stalker 2 called GetRawInputData, it hit Steam's hook first, which then forwarded the call to our hook. Because Steam was the "caller" of our hook, our whitelist mistakenly identified Stalker 2's request as a legitimate Steam UI request and allowed the real inputs to flow back to the game engine through Steam's proxy chain. **Fixed** by completely removing the whitelist and creating a "blind block" that zeroes all inputs process-wide. Because Steam's actual overlay inputs are processed by steam.exe via IPC rather than the injected DLL hooks, this safely isolates the game without blinding the Steam UI.

## 8. Thread Profiling and Raw HID USB Blocking
* **The Steam Hooks Impersonation (Attempt 2):** Since _ReturnAddress() failed because Steam's API hooks act as a middle-man for the game's calls, we couldn't whitelist the Steam Overlay. **Fixed** by using NtQueryInformationThread to read the OS-level memory structure of the calling thread, tracing it back to the exact .dll that spawned it. We now successfully bypass our firewall ONLY for threads genuinely spawned by steamclient64.dll.
* **The Native DualSense USB Drop:** Our intercept blocked ReadFile and DeviceIoControl by returning ERROR_DEVICE_NOT_CONNECTED. This caused the game to drop the USB connection and swap its UI glyphs to Mouse/Keyboard. When the overlay closed, the game took several seconds to handshake with the controller again. **Fixed** by maintaining the handle connection and building a thread-safe map of OVERLAPPED buffers. When Steam Overlay opens, we intercept the async completion and overwrite the payload with a perfectly neutralized DualSense packet (axes at 128, buttons zeroed) on-the-fly, preventing UI glyph swaps and connection loss.

## 8. Thread Profiling and Raw HID USB Blocking
* **The Steam Hooks Impersonation (Attempt 2):** Since _ReturnAddress() failed because Steam's API hooks act as a middle-man for the game's calls, we couldn't whitelist the Steam Overlay. **Fixed** by using NtQueryInformationThread to read the OS-level memory structure of the calling thread, tracing it back to the exact .dll that spawned it. We now successfully bypass our firewall ONLY for threads genuinely spawned by steamclient64.dll. *(Note: Later removed in favor of total game blind block).* 
* **The Native DualSense USB Drop:** Our intercept blocked ReadFile and DeviceIoControl by returning ERROR_DEVICE_NOT_CONNECTED. This caused the game to drop the USB connection and swap its UI glyphs to Mouse/Keyboard. When the overlay closed, the game took several seconds to handshake with the controller again. 
* **The IOCP Bypass (Async Map Failure):** We attempted to solve the USB drop by building an async map to intercept `GetOverlappedResult`. However, Unreal Engine uses I/O Completion Ports (IOCP) which completely bypasses `GetOverlappedResult` and reads the raw kernel memory directly, allowing physical button presses to bleed through. **Fixed** by reverting to a completely synchronous `ReadFile` intercept that returns `TRUE` immediately. This completely isolates the IOCP queue from the kernel, feeding the engine a fake neutralized packet instead.
* **The Enhanced Mode D-Pad Up Bug:** When constructing the spoofed DualSense packet, we mistakenly used the DualShock 4 layout (buttons at `buf[5]`) instead of the Enhanced DualSense layout (buttons at `buf[8]`). This inadvertently forced the D-Pad to "UP", causing continuous menu navigation bugs. **Fixed** by placing `0x08` (neutral) perfectly in `buf[8]`.
* **The Gyroscope 0G Freefall Bug:** Synthesizing an empty `0x00` packet caused the Accelerometer Z-axis to report `0` gravity. When Unreal Engine calculated the orientation pitch/yaw, it resulted in a `NaN` math error, snapping the camera to `0, 0` (Top-Left). **Fixed** by spoofing a stationary 1G value (`8192` or `0x2000`) in `buf[26-27]`.
* **The Buggy Touchpad Parser Bug:** Setting the "Not Touching" bit on the touchpad was insufficient if the game engine possessed a buggy parser that evaluated X/Y variables regardless. **Fixed** by mathematically centering the idle X/Y packet coordinates at `960x540` (the precise center of the 1920x1080 Touchpad matrix) to defeat lazy parsing algorithms.

## 9. Game Unfocused Focus Loss
* **The Unfocused Bleed-Through:** We were exclusively triggering our firewall when `g_bIsSteamOverlayActive` was True. This meant tabbing out of the game (Alt-Tab) still allowed inputs to reach the engine if the Steam Overlay was closed. **Fixed** by spinning up a 20Hz `BackgroundWorker` to poll `GetForegroundWindow()`. We now combine this with the Steam state into a unified `ShouldBlockInput()` check, blinding the game perfectly when unfocused.

## 10. Steam Overlay IPC Leakage (Unfixable DX12 Edge Case)
* **The Background Overlay Navigation:** When the game loses focus, the game engine correctly blocks all input, but the Steam Overlay inside the game continues to receive navigation inputs. **Unfixable:** Investigation into Steam log files (gameoverlay_renderer.txt and controller_ui.txt) proved that the Steam Overlay UI is actually powered by a completely separate process (steamwebhelper.exe). steam.exe reads the controller natively and forwards the inputs directly to steamwebhelper.exe via IPC. Because Stalker 2 uses DX12 Flip Model for HDR, Alt-Tabbing does not minimize the swapchain, so steam.exe refuses to suspend the IPC stream. Because the input processing happens entirely in a separate process, it is impossible to intercept or block with our proxy DLL inside the game process without crashing the swapchain. Attempting to force-strip RIDEV_INPUTSINK caused video corruption and was successfully reverted.

### 11. Kernel-Level Media Corruption & Hot-Swap Recycling
* **The Handle Reuse Leak:** We successfully intercepted DualSense raw USB data by hooking `CreateFile`, `ReadFile`, and `DeviceIoControl`. However, we originally forgot to hook `CloseHandle`. 
When the game closed a DualSense USB connection, our proxy kept the OS Handle ID (e.g. 0x15C) on its internal Watch List. Because Windows aggressively recycles handle IDs to save memory, the OS 
would frequently assign the exact same 0x15C handle ID to subsequent media streams (like the main menu background video or audio .pak files). When the Steam Overlay was opened, our proxy 
intercepted the media stream's `ReadFile` call, falsely identified it as a controller, and overwrote the video/audio buffer with fake DualSense joystick data (0x01, 0x80...), causing severe video 
macro-blocking and audio screeching. **Fixed** by hooking `CloseHandle` with a high-performance scope-based lock to instantly remove closed handles from the Watch List.
* **The RawInput Device Swap Bug:** While `CloseHandle` fixed Kernel file handles, RawInput devices provided by the OS Kernel do not use `CloseHandle`. If a user hot-swapped controllers (unplugged a non-Sony controller and plugged in a DualShock 4), the OS often recycled the `RAWINPUTHEADER.hDevice` ID. Our caching mechanism would see the recycled handle, assume it was still a "non-Sony" device, and fail to neutralize it. **Fixed** by intercepting the `WM_INPUT_DEVICE_CHANGE` (0x00FE) broadcast and pruning the `GIDC_REMOVAL` (0x2) handle explicitly from all caches, completely securing hot-swap scenarios.
* **The Sony Blanket Match:** Our original `CreateFile` hook identified DualSense controllers simply by checking if the hardware path contained `vid_054c` (Sony Corporation). This inadvertently 
matched all Sony devices, including PlayStation VR headsets, Sony Pulse 3D Headsets, and Sony Bravia TVs (via EDID queries). Intercepting these endpoints corrupted non-controller audio and video 
data. **Fixed** by explicitly requiring the hardware path to also match the specific DualSense (`pid_0ce6`, `pid_0df2`) or DualShock 4 (`pid_05c4`, `pid_09cc`) Product IDs.
